# Решение

## Что сделано

- Сохранён существующий публичный API роутера, store, event и sender.
- Добавлена поддержка события `billing-refund`.
- Добавлен маппинг имени события для MMP:
  - `billing-payment` -> `purchase`;
  - `billing-refund` -> `refund`.
- Добавлен статус `GDPR_NOT_APPROVED`.
- Сохранена валидация положительной суммы для payment и refund.
- Добавлены table-driven тесты для refund:
  - успешная отправка;
  - нулевая и отрицательная сумма;
  - отсутствие mapping;
  - выключенный проект;
  - временная и постоянная ошибки sender;
  - проверка имени события в payload.

## Как запустить

Нужен Go 1.22 или новее.

```bash
go test ./...
go run ./cmd/router
```

Для другого каталога с JSON-файлами:

```bash
go run ./cmd/router -data ./testdata
```

## Открытые вопросы PM

Следующие решения намеренно не принимаются без уточнения:

1. Что означает `consent_check_enabled: null`:
   - выключенная проверка;
   - включённая проверка с deny-by-default;
   - отдельная ошибка или статус.
2. Какой порядок должен быть между GDPR-проверкой и поиском MMP mapping.
3. Входит ли `DryRun=1` в scope и должен ли он устанавливать `Payload.Sandbox=true`.
4. Нужно ли расширять `testdata/events.json`, или достаточно unit-тестов.

До ответа PM GDPR-проверка и mapping `DryRun` не добавляются, чтобы не фиксировать неподтверждённое бизнес-поведение.

## Проверки
